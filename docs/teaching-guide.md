# Cloudflare 后续课程的教学约定

保留现有学习项目。目标是让学习者能够判断什么时候需要一个功能，以及怎样让程序自动使用它。不能把接口成功或资源已配置当成理解功能的证据。

每一课按下列顺序展开：

1. **实际问题**：具体工作场景、原做法的成本、功能改善的那一步，以及什么时候不需要它。
2. **最多三个核心概念**：术语首次出现用普通话解释，与网页、程序、数据库查询等熟悉的事物建立联系。
3. **完整逻辑**：简单流程图说明谁触发、程序做什么、Cloudflare 做什么、数据在哪里、最后得到什么。涉及数据时说明首次、再次、变化和失效后的行为。
4. **人工与程序分工**：区分开发者一次性设置、程序每次自动执行、用户或运营决定。程序可以自动做的事情，不能声称 Cloudflare 默认会做。
5. **一个最小完整实例**：说明观察什么、证明什么，以及证明不到什么。真实实现、本地模拟、未来扩展明确标记；资源未开通时不能伪造成功。

默认页面只保留实际问题、核心概念、流程（含分工）、一个实例。命令、代码、配置、额度和详细文档折叠。简洁意味着减少干扰，不意味着删掉解释因果关系的内容。

主动解释边界：与上一课的区别、资源归属账号还是项目、能否共用、谁保存/更新/删除数据、传播延迟和影响用途的限制。

用当前 Cloudflare 官方文档核对事实，链接放在对应说明或折叠区。语气像耐心的同事，不假设学习者懂产品术语。后续新课程先遵守本约定；不擅自重写已完成的课程。
